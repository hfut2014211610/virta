# 混合数据识别说明（bar-basic / line-basic）

> 目的：当输入不是“干净表”时，先告诉读图的人：我识别了什么、忽略了什么、哪里需要复核。宁可把脏数据摊开，也不要静默画出一个看似正确的图。

## 1. 识别顺序

1. **文件解析**：CSV / JSON / XLSX；CSV 用 `utf-8-sig` 容忍 BOM。
2. **表头归一化**：去空格、去 `_ - .` 等符号，统一小写后再匹配别名。
   - 分类别名：`label/name/category/x/分类/类别/标签/名称`
   - 系列别名：`series/group/系列/分组/渠道/门店/城市/部门`
   - 数值别名：`value/count/amount/y/数值/数量/金额/销量/营收`
3. **数值列判定**：整列解析率 `>= 80%` 视为数值列；否则视为文本列，不强行聚合。
4. **结构选择**：
   - 有系列列 → 长表 `label + series + value`
   - 无系列列、≥2 个数值列 → 宽表，每个数值列为一个系列
   - 否则 → 单系列；需要数值列，否则直接报错
5. **ECharts JSON**：走 `xAxis.data + series[].name + series[].data` 透传路径。

## 2. 可解析的数值形态

| 输入 | 结果 | 备注 |
|---|---|---|
| `1200` / `1,200` / `1，200` | `1200` | 千分位逗号/中文逗号 |
| `¥1,200` `$980` `€76` `￥88` | `1200` 等 | 货币符号剥离 |
| `(1,234)` | `-1234` | 括号负数 |
| `+12` / `8.5%` | `12` / `8.5` | 百分号保留原刻度 |
| `N/A` `null` `-` `—` `缺失` | `0` + 计数 | 按 0 计，不静默 |
| `abc` | `0` + 计数 | 非法值进入警告 |

设计取舍：**百分号不转换为 0.x**。同一列混入 `85%` 与 `980` 本质上不是同一量纲，系统只保留原始刻度并警告，避免把百分比偷偷缩小 100 倍。

## 3. 输出中的识别报告

产物 HTML 会多一个 `.quality` 区块，展示：

- 识别模式：`long / wide / single / echarts`
- 字段映射：`label=分类`、`series=渠道`、`value=金额`
- 行数、缺失按 0 计数量、非法按 0 计数量、重复 label/series 求和次数
- 置信度：`high / medium / low`
- 最多 6 条警告，避免数据问题被图表噪音淹没

## 4. 置信度规则

- `high`：无缺失、无非法、无百分号
- `medium`：有缺失或百分号，但无非法值
- `low`：存在无法解析的非法值

## 5. 安全性

- 所有用户数据进入 HTML 前统一 `html.escape`
- 内嵌 JSON 中的 `<` 会替换为 `\u003c`，避免用户数据里的 `</script>` 截断页面
- 表格、图例、tooltip 数据通道不再直接拼接未转义字符串

## 7. 行类型标记（瀑布图可选）

如果输入包含 `类型` 列，会被识别为行类型，不参与数值聚合：

- `delta` / `增减` / `变动` / `差额`：增减项，按前一水位累计
- `absolute` / `subtotal` / `total` / `小计` / `合计` / `总计` / `累计`：锚点项，直接从 0 绘制
- 未知标记：按 delta 处理，并写入数据识别报告
- 同一分类出现多种行类型：按首次出现绘制，并写入报告

没有类型列时，所有行默认按 delta 处理。

## 6. 仍需人工复核的情况


- 列名同时像分类又像数值（如 `2024`）
- 同一列混用货币与百分号
- 宽表里混入大量文本注释列
- 重复 label/series 组合是“采集错误”还是“业务累计”

这些不会被自动“修正”，而是明确标红/标黄；是否重跑数据由业务方决定。
